# Руководство по версионированию пресетов

## Создание нового релиза

### Автоматический способ (рекомендуется)

1. **Создайте тег с версией:**
   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```

2. **Или используйте аннотированный тег:**
   ```bash
   git tag -a v0.1.0 -m "Release version 0.1.0"
   git push origin v0.1.0
   ```

3. **GitHub Actions автоматически создаст релиз** при пуше тега.

### Формат версий

Используйте семантическое версионирование:
- **v0.1.0** - Первый релиз
- **v0.1.1** - Патч (исправления ошибок)
- **v0.2.0** - Минорная версия (новые пресеты, новые промпты)
- **v1.0.0** - Мажорная версия (критические изменения)

### Ручной способ через GitHub UI

1. Перейдите в раздел **Releases** на GitHub
2. Нажмите **"Draft a new release"**
3. Выберите тег или создайте новый
4. Заполните название и описание
5. Нажмите **"Publish release"**

### Автоматическое создание релиза через workflow_dispatch

Можно запустить создание релиза вручную через GitHub Actions:

1. Перейдите в **Actions** → **Create Release**
2. Нажмите **"Run workflow"**
3. Введите версию (например, `v0.1.0`)
4. Нажмите **"Run workflow"**

## Структура версий

### Версия v0.x.x (Бета/Разработка)
- Добавление новых пресетов
- Изменение промптов
- Исправление ошибок

### Версия v1.x.x (Стабильная)
- Стабильная версия пресетов
- Обратная совместимость
- Документация

## Чек-лист перед релизом

- [ ] Все пресеты имеют `context_entry.md`
- [ ] Все `files_config.json` валидны
- [ ] Обновлен `README.md` (если есть)
- [ ] Протестирована загрузка пресетов через программу
- [ ] Создан тег с версией

## История релизов

Релизы автоматически создаются при пуше тегов. Посмотреть все релизы можно на странице [Releases](https://github.com/vladcraftcom/ai_prompt_presets/releases).
