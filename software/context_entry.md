# Context Entry Point - Software Development Preset

**🎯 Точка входа для ИИ**

Этот файл описывает порядок чтения промптов и файлов для погружения в контекст пресета "Разработка ПО".

## 📚 Порядок чтения для понимания контекста

### Шаг 1: Основной промпт разработки
**Начни с:** `prompt_cursor_skeleton.md` (копируется в проект как `cursor_prompt.md`)

Это основной промпт, который определяет:
- Роль ИИ (Senior Automation Engineer)
- Правила работы и методологии
- Процесс разработки (консультация → вопросы → план → код → тесты → аудит)
- Обязательную проверку и установку инструментов окружения
- Языковую агностичность проекта
- Требования к структуре проекта и логированию

**Важно**: Этот промпт содержит обязательный первый этап - проверку и установку необходимых инструментов перед началом разработки.

### Шаг 2: Консультативный промпт (опционально)
**Файл:** `prompt_expert.md` (копируется в проект как `prompt_expert.md`)

Используй этот промпт, если пользователь запрашивает консультацию перед началом разработки:
- Замени `{ОТРАСЛЬ}` и `{РОЛЬ}` на конкретную предметную область
- Проведи консультацию согласно шаблону
- Сохрани результаты консультации для использования в дальнейшей работе

### Шаг 3: Правила логирования
**Файл:** `log_manifest.ai.md` (копируется в проект как `log_manifest.ai.md`)

Изучи правила логирования перед началом работы:
- Формат записи в `run_log.txt`
- Правила документирования операций
- Требования к транскрипции в `chat_transcript.md`

### Шаг 4: Промпт аудита (для финальной проверки)
**Файл:** `prompt_auditor.md` (копируется в проект как `prompt_auditor.md`)

Используй этот промпт на завершающем этапе:
- После завершения разработки
- Для проверки качества кода
- Для аудита промптов и процесса
- Сохрани результаты в `audit_report.md`

## 🔄 Типичный workflow

1. **Начало работы**: Прочитай `cursor_prompt.md` полностью
2. **Консультация** (если запрошена): Используй `prompt_expert.md`
3. **Во время работы**: Следуй правилам из `log_manifest.ai.md`
4. **Завершение**: Используй `prompt_auditor.md` для финального аудита

## 📝 Структура проекта

- `code/` - исходный код проекта
- `data_in/` - входные данные
- `data_out/` - выходные данные и результаты
- `logs/` - логи работы (опционально, если нужна отдельная папка)
- `plan.md` - детальный план разработки
- `chat_transcript.md` - транскрипция переписки с пользователем
- `run_log.txt` - лог выполнения операций
- `audit_report.md` - отчет аудита (создается после аудита)
- `changelog.md` - история изменений

## 🚀 Первый запуск проекта

После прочтения всех промптов:
1. Проверь наличие необходимых инструментов (обязательный первый этап из `cursor_prompt.md`)
2. Если инструменты отсутствуют - установи их автоматически (если доступны curl/wget) или предоставь инструкции
3. Сохрани информацию о проверке окружения в `environment_check.md`
4. Начни работу согласно процессу из `cursor_prompt.md`

---

**💡 Совет**: Всегда начинай с `cursor_prompt.md` - это основной документ, который определяет весь процесс работы над проектом.
